# Security policy

## Supported versions

Security fixes ship on the latest release of dimmi and on dimmi Cloud. Older releases do not receive backports.

| Version | Supported |
| --- | --- |
| Latest release | Yes |
| Earlier releases | No |

## Reporting a vulnerability

Do not open a public GitHub issue or pull request for a security bug. Report it in private using one of these channels:

- **GitHub private vulnerability reporting:** open a draft advisory at [github.com/dimmihq/dimmi/security/advisories/new](https://github.com/dimmihq/dimmi/security/advisories/new).
- **Email:** send the report to [support@trydimmi.com](mailto:support@trydimmi.com) with "Security" in the subject line.

## What to include

Include enough detail for us to reproduce the issue:

- Affected component, endpoint, or SDK package.
- dimmi version or commit SHA, and whether you saw it on dimmi Cloud or a self-hosted server.
- Steps to reproduce, proof-of-concept request, or logs.
- Impact on workspace data, accounts, or tenants.

## What to expect

We review reports in private, confirm whether we can reproduce the bug, and work with you on a fix before public disclosure. Keep the report private until a patched release is out.

For details on how dimmi Cloud protects workspace data, see our [security documentation](https://trydimmi.com/docs/workspace/security/) and [privacy policy](https://trydimmi.com/privacy).
