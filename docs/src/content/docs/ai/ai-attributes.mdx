---
title: "AI attributes"
description: "Have AI note the same few facts on every conversation, like intent or order number, and use them in workflows and views."
---

Some facts matter on every conversation: what the customer wants, which order they mean, whether they're on a trial. Asking teammates to tag these by hand never sticks, and a workflow can't read them from the words alone.

An **AI attribute** is one of those facts, defined once in **Settings → AI attributes**. dimmi reads each conversation and fills it in, then checks again as the customer writes. Workflows branch and start on the value, and inbox views filter by it.

## Define an attribute

Give each attribute a name, a type and a description. The description is what the AI reads, so write it the way you'd brief a new teammate.

| Name | Type | Description |
| --- | --- | --- |
| Intent | One of a list: `refund`, `bug`, `question`, `other` | The customer's main reason for writing. |
| Order number | Text | The order the customer is writing about, such as `A-1042`. |
| On a trial | Yes or no | Whether the customer says they're still on a free trial. |

Types are text, number, date, yes or no, and one of a list. The key (`intent`, `order_number`) and the type are fixed once saved. Turning off **Detect on conversations** archives an attribute and keeps the values it already found.

## How values are found

The decision model reads the whole conversation and answers for every active attribute at once. When it fails, it's asked again, then your workspace's own AI provider answers instead.

- **Only sure values are kept.** When the AI isn't sure, the attribute stays empty. It never guesses to fill the field.
- **Values update as the conversation goes.** Each customer message starts a fresh check about 20 seconds later, at most once a minute. A sure new value replaces the old one; an unsure answer leaves the old one in place.
- **Archived attributes keep their values**, so workflows and views that read them keep working.

## Use attributes in workflows

Every attribute reads as `conversation.ai.<key>`:

- **Branch** on it, like "AI: Intent is any of `refund`".
- **Start a workflow** with the **AI attribute changes** trigger. It fires each time a value is set or changes, and its conditions can read **Changed AI attribute** and **New AI value**.
- **Use it in text** as a variable, like `{{conversation.ai.order_number}}`, or map it into a [Run an action](/workflows/triggers-and-steps/#team) input.

## Use attributes in views

In a [view](/inbox/views/), add a condition on **AI: Intent**, for example, to list every open refund request.

## Rules and limits

| Rule | Limit |
| --- | --- |
| Active attributes per workspace | 30 |
| Values of a list | 1 to 30, 80 characters each |
| Name | 80 characters |
| Description | 500 characters |
| How often a conversation is read again | About 20 seconds after a customer message, at most once a minute |

The API lists attributes at `GET /api/v1/ai/conversation-attributes` and a conversation's values at `GET /api/v1/conversations/{conversation}/ai-attributes`.
