---
title: "What customer data the dimmi agent sees"
description: "See what dimmi sends to your AI provider, what personal data gets masked automatically, and what you can turn off."
---

By default, the dimmi agent sends your AI provider only the conversation messages and the customer's first name and locale. You can change these privacy settings in **Settings → dimmi agent**, under **Privacy**.

## What reaches the AI model

Each time the agent writes a reply, dimmi sends four things to the model:

- **Messages:** customer messages, teammate replies, and past agent replies. Internal notes are never sent.
- **Customer details:** with **Basic** (the default), only the customer's first name and locale. With **None**, no profile details are sent.
- **Knowledge:** matching passages from your help center and [knowledge sources](/ai/knowledge-sources/).
- **Action results:** only the fields you listed in **Fields to keep**, or the full response if you left that list empty.

Bound values on an [action](/ai/actions/), such as `{contact.email}`, go straight to your API and are never shown to the AI model.

## Hide personal data

**Hide personal data** is on by default. Before any message leaves dimmi, sensitive strings are replaced with placeholders:

| In the message | What the model sees |
| --- | --- |
| Email address | `[email]` |
| Phone number | `[phone]` |
| Payment card number | `[card ending 4242]` |
| IBAN | `[iban]` |
| US Social Security number | `[ssn]` |
| API key, token, or password | `[secret]` |

A few details to keep in mind:

- **Order details stay readable:** order numbers, dates, and invoice IDs pass through unmasked so the agent can look them up.
- **Saved traces match:** the reply traces dimmi stores keep the masked text.
- **Action results stay protected:** card numbers, IBANs, Social Security numbers, and secrets are always masked in action responses, even if you turn **Hide personal data** off.

With masking on, the agent cannot read an email address typed in chat. If an action needs the customer's email, bind `{contact.email}` on the action instead.
