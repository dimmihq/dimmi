---
title: "API rate limits"
description: "See the default rate limit windows for API tokens and workspaces, and the headers to inspect on 429 responses."
---

dimmi enforces four rate limit windows. Crossing any window returns `429` with `code: "too_many_requests"`.

## Default windows

Self-hosted installs can tune these in [configuration options](/self-hosting/configuration-options/).

| `X-RateLimit-Scope` | Scoped to | Default limit |
| --- | --- | --- |
| `burst` | Single API token | 100 requests / 10 seconds |
| `token` | Single API token | 600 requests / minute |
| `workspace` | All API tokens in a workspace | 6,000 requests / minute |
| `user` | Signed-in user (session auth) | 1,200 requests / minute |

Any IP address that sends 60 rejected token requests in 1 minute also receives `429` until the minute resets.

## Rate limit headers

| Header | Returned on | Meaning |
| --- | --- | --- |
| `X-RateLimit-Limit` | Every response | Max requests in the token's 1-minute window. |
| `X-RateLimit-Remaining` | Every response | Remaining requests in that window. |
| `X-RateLimit-Scope` | `429` | Which window triggered the limit. |
| `Retry-After` | `429` | Seconds to wait before retrying. |
| `X-RateLimit-Reset` | `429` | Unix timestamp (seconds) when the window resets. |

On a `429` response, `X-RateLimit-Limit` and `X-RateLimit-Remaining` reflect the window that tripped. All official [SDKs](/developers/sdks/supported-versions/) respect `Retry-After` and retry automatically.
