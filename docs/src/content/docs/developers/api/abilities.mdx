---
title: "API token abilities"
description: "Every ability an API token can hold and the endpoints each one opens."
---

Each endpoint in the [API reference](/api-reference/) names the ability it needs. A request without it gets `403` with code `missing_ability` and the ability's name in `required_ability`.

## Abilities

You can give a token only the abilities your role holds a permission in.

| Ability | Opens |
| --- | --- |
| `conversations:read` | Read conversations, messages, inboxes, tags, saved replies, conversation reports and data exports. |
| `conversations:write` | Create and change conversations, send replies and notes, change saved replies, create tags. |
| `contacts:read` | Read customers (`contact` in the API), companies, attribute and event definitions, email suppressions. |
| `contacts:write` | Create, change, import and erase customers and companies, track customer events. |
| `attributes:write` | Change attribute and event definitions. |
| `audiences:read` | Read audiences. |
| `audiences:write` | Create, change and delete audiences. |
| `tickets:read` | Read tickets, their events, types, states and ticket reports. |
| `tickets:write` | Create and change tickets, their links and linked issues. |
| `articles:read` | Read help centers, articles and collections. |
| `articles:write` | Create and change articles and collections. |
| `changelog:read` | Read changelog entries, labels and subscribers. |
| `changelog:write` | Create and change changelog entries, labels and subscribers. |
| `feedback:read` | Read feature request boards, posts and statuses. |
| `feedback:write` | Create and change feature request posts and comments. |
| `broadcasts:read` | Read broadcasts and topics. |
| `broadcasts:write` | Create and change broadcasts and topics. |
| `series:read` | Read series and their enrollments. |
| `series:write` | Create and change series. |
| `workflows:read` | Read workflows and schedules. |
| `workflows:write` | Create and change workflows and schedules. |
| `ai:read` | Read the dimmi agent's settings, actions, runs and procedures. |
| `ai:write` | Change the dimmi agent's settings and procedures. |
| `ai:actions` | Create, change and publish actions and their connections. |
| `ai:keys` | Add, change and delete AI provider keys. |
| `members:read` | Read members, invitations, teams, roles and permissions. |
| `members:write` | Change members, invitations and teams. |
| `webhooks:read` | Read webhook endpoints, deliveries and event types. |
| `webhooks:write` | Create and change webhook endpoints, send deliveries again. |
| `settings:read` | Read workspace settings: channels, email, messenger settings, integrations, knowledge sources, SLA policies, the audit log. |
| `settings:write` | Change those settings, and inboxes, help centers, ticket types, states and fields, feature request boards. |

The abilities `notifications:read`, `notifications:write`, `exports:read`, `exports:write`, `engage:read`, `engage:write`, `billing:read`, `billing:write`, `system:read` and `system:write` open no endpoint in the API reference.

## Endpoints without an ability

| Endpoints | Token access |
| --- | --- |
| `GET /me`, `GET /workspace`, `GET /workspace/entitlements` | Any token. |
| Other endpoints with no ability in the reference, such as single sign-on and custom role changes | None. They answer `403` with code `credential_not_accepted`. |
