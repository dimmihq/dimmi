---
title: "Messenger API"
description: "The HTTP API the dimmi messenger uses, for building your own chat interface."
---

The messenger's HTTP API is at `/widget/v1` on `https://trydimmi.com`, or on your own dimmi address when self-hosted.

Requests and responses are JSON, and the API reads and sets no cookies.

## Start a session

```bash
curl https://trydimmi.com/widget/v1/sessions \
  -H "Content-Type: application/json" \
  -d '{"app_id": "<app_id>"}'
```

`<app_id>` is the messenger's app ID (`wgt_...`) from **Settings → Messengers**. The `201` response carries `data.token` (`dmi_ws_...`) once: store it and send it as `Authorization: Bearer <session_token>` on each later request.

| Field | Use |
| --- | --- |
| `user_jwt` | An [identity token](/developers/messenger/identity-verification/). The session then belongs to that customer. |
| `previous_token` | The session token you held before, sent with `user_jwt`. dimmi merges an anonymous session's customer into the signed-in one. |
| `locale`, `timezone` | The customer's language tag and IANA time zone. |
| `page` | The page the customer is on: `url` (required), `title`, `referrer`. |
| `website` | Leave it out. dimmi treats a session that fills it as a bot and files its conversations as spam. |

## Send a message and read replies

```bash
curl https://trydimmi.com/widget/v1/conversations \
  -H "Authorization: Bearer <session_token>" \
  -H "Content-Type: application/json" \
  -d '{"client_id": "7f9c2b1e-4a53-4d0e-9c1f-2b6a8e0d3f15", "body": "Where is my order?"}'

curl "https://trydimmi.com/widget/v1/updates?since=<cursor>" \
  -H "Authorization: Bearer <session_token>"
```

`client_id` is a UUID you create for each message. A retry with the same `client_id` stores the message once.

Leave `since` out on the first call to `/updates`. Each response has `meta.cursor` to pass as the next `since`, `meta.poll_after_ms` to wait before asking again, and `meta.has_more`.

| `event` in `/updates` | `payload` |
| --- | --- |
| `message.created`, `message.updated`, `message.deleted` | The message. |
| `conversation.updated`, `conversation.closed` | The conversation. |

## Endpoints without a session

Each of these names the messenger in its path or body.

| Endpoint | Returns or does |
| --- | --- |
| `POST /sessions` | Starts a session. |
| `GET /apps/{app}/config` | The messenger's settings: appearance, texts, features. |
| `GET /apps/{app}/availability` | Whether the team is in office hours, and the reply time to show. |
| `GET /apps/{app}/help` | The help center collections and articles anyone may read. |
| `GET /apps/{app}/changelog` | Published changelog entries. |
| `GET /apps/{app}/ticket-types` | The ticket types a customer may open. |
| `POST /apps/{app}/article-views` | Counts one article view. |

## Endpoints with a session

| Endpoint | Returns or does |
| --- | --- |
| `GET /session` | The session, its customer and unread count. |
| `PATCH /session` | Renews a signed-in session with a fresh `user_jwt`. |
| `DELETE /session` | Ends the session. |
| `GET /contact`, `PATCH /contact` | The customer's profile. `PATCH` takes `name`, `email`, `phone` and `custom_attributes`. |
| `POST /email-verifications` | Mails a code to `email`. |
| `POST /email-verifications/checks` | Checks the `code` the customer typed. |
| `GET /conversations` | The customer's conversations, latest activity first. `filter[status]` takes `open` or `closed`. |
| `POST /conversations` | Starts a conversation with a first message. |
| `POST /openers` | Starts a conversation before the customer writes, so a [workflow](/workflows/how-workflows-work/) can greet them. |
| `GET /conversations/{conversation}` | One conversation. |
| `GET /conversations/{conversation}/messages` | Messages, oldest first. Takes `before`, `after` and `limit` (at most 100). |
| `POST /conversations/{conversation}/messages` | Sends a message: `client_id`, `body`, `attachment_ids` (at most 10), or `choice` for a button the customer picked. |
| `PATCH /conversations/{conversation}/read-state` | Marks messages read up to `last_read_message_id`. |
| `POST /conversations/{conversation}/typing-indicators` | Shows the team that the customer is typing. |
| `POST /conversations/{conversation}/ai/helped` | Confirms the dimmi agent resolved the conversation. |
| `POST /conversations/{conversation}/ai/handoff` | Asks for a handover to a teammate. |
| `GET`, `PATCH /conversations/{conversation}/action-calls/{call}` | An [action](/ai/actions/) waiting for the customer. `PATCH` takes `status`: `confirmed` or `canceled`. |
| `GET`, `PATCH /conversations/{conversation}/rating` | The conversation's rating. `PATCH` takes `score` (1 to 5) and `comment`. |
| `POST /attachments` | Announces a file: `filename`, `content_type`, `size_bytes`. Send the bytes to `data.upload.url` with its `method` and `headers`. |
| `PATCH /attachments/{attachment}` | With `status: "uploaded"`, finishes the upload so a message can name it in `attachment_ids`. |
| `GET /ticket-types`, `GET /tickets`, `GET /tickets/{ticket}` | The ticket types and the customer's tickets. |
| `POST /tickets` | Opens a ticket: `client_id`, `type_id`, `title`, `description`, `fields`. |
| `GET /help` | The help center content this customer may read. |
| `POST /help-passes` | A link that opens the help center with the customer signed in. |
| `POST /article-views`, `POST /article-ratings` | Counts an article view, stores an article rating. |
| `POST /events` | Records 1 to 20 [events](/developers/messenger/track-events/) for the customer. |
| `POST /pings` | Records the page the customer is on. |
| `POST /realtime-tokens` | A token for the live event stream the dimmi messenger reads instead of polling. |
| `GET /updates` | What changed since a cursor, at most 100 changes per response. |

## Errors and limits

An error response is `{"code": "...", "message": "...", "errors": {}}`. A `401` with the code `session_invalid`, `session_expired` or `session_revoked` means the session is over: start a new one.

A browser request must come from a site in **Allowed sites** in the messenger's settings, when that list has entries. A request with no `Origin` header then needs the messenger's `native_apps_enabled` setting, which the [REST API](/api-reference/) sets.

| Limit | Each session | Each network |
| --- | --- | --- |
| Messages | 20 per minute | 600 per hour |
| New conversations | 5 per hour | 60 per hour |
| File uploads | 10 per minute | 300 per hour |
| Event batches | 30 per minute | 3,000 per hour |
| Message `body` | 64 KB | |
