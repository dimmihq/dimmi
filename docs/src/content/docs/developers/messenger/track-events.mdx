---
title: "Track customer events"
description: "Record what customers do in your product as events, from your server with POST /api/v1/contact-events or from the browser with trackEvent()."
---

[Audiences](/customers/audiences/) and [series](/outbound/series/) filter on a customer's events, and each event sends the `contact_event.tracked` [webhook](/developers/webhooks/events/).

An event name is 1 to 64 lowercase letters, digits and `_ . : -`. Metadata is optional: at most 20 keys and 2 KB.

## Send events from your server

[`POST /api/v1/contact-events`](/api-reference/contacts-and-companies/create-contact-event/) needs an API token with the `contacts:write` ability.

```bash
curl -X POST https://app.trydimmi.com/api/v1/contact-events \
  -H "Authorization: Bearer <api_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "order.placed",
    "external_id": "42",
    "metadata": { "order_id": "A-1001", "total": 129.5 },
    "idempotency_key": "order-A-1001"
  }'
```

- Name the customer with exactly one of `contact_id`, `email` or `external_id`, which is the `sub` of their [identity token](/developers/messenger/identity-verification/).
- dimmi counts an `idempotency_key` once in 48 hours.
- To send up to 100 events in one request, put them in an `events` array.

## Send events from the browser

```ts title="src/checkout.ts"
import { getDimmi } from "@dimmi/browser";

getDimmi().trackEvent("checkout.started", { plan: "team", seats: 5 });
```

With the script tag, call `Dimmi("track", "checkout.started", { plan: "team", seats: 5 })`.

Anyone on the page can forge a browser event. The messenger sends only the event names you switch on under **Events** in **Settings → Attributes**, or every name with **Accept any event from the messenger**. Send from your server any event an audience or series must trust.

The messenger holds events until the customer has a session: a signed-in customer, or a visitor who has written before.
