Your server signs a short-lived JWT for the signed-in user, and the messenger signs them in as the customer its `sub` claim names.

## Create a secret

Create a **Shared secret (HS256)** in **Settings → Identity verification** and store its two values on your server:

```bash title=".env"
DIMMI_IDENTITY_SECRET=dmi_idsec_<secret>
DIMMI_IDENTITY_KID=isk_<key_id>
```

To sign with your own RSA, P-256 or Ed25519 key instead, add its public key as a secret and set `DIMMI_IDENTITY_PRIVATE_KEY` to the private key's PEM text.

## Sign a token on your server

`@dimmi/server` and `@dimmi/nextjs` read those variables and sign tokens that live 600 seconds (`expiresIn`, at most 3,600).

The user object takes `id` (required), `email`, `emailVerified`, `name`, `phone`, `avatarUrl`, `locale`, `timezone`, `signedUpAt`, `company` and `attributes`.

The [Go](/developers/sdks/go/), [PHP](/developers/sdks/php/), [Laravel](/developers/sdks/laravel/) and [Python](/developers/sdks/python/) SDKs sign tokens too. With any other JWT library, use the whole `dmi_idsec_` string as the HMAC key without base64-decoding it, and put the key ID in the `kid` header.

## Pass the token to the messenger

On Next.js, the `identity` prop in the layout does this. Every other package takes one of two options.

- **`identityUrl`** (`data-identity-url` on the script tag), such as `/api/dimmi/token`: a URL on the page's own origin that answers `200` with `{"token": "<jwt>"}`, or `{"token": null}` when nobody is signed in.
- **`identity`**: a function that returns the token or `null`.

The messenger asks for a token on each page load. In a single-page app, call `identify()` after sign-in and `shutdown()` after sign-out (`refreshDimmiIdentity()` and `dimmiLogout()` in `@dimmi/nextjs`).

## Claims

dimmi requires `sub` and `exp`, and drops any other claim in the wrong shape.

| Claim | Rule |
| --- | --- |
| `sub` | Your user's ID, a string of 1 to 255 characters. |
| `exp` | Expiry in seconds since the epoch, at most 7 days after `iat`. dimmi forgives 60 seconds of clock skew. |
| `aud` | `dimmi`, the messenger's app ID or the workspace ID. Leave it out to accept any messenger. |
| `nonce` | Up to 128 characters. A token with a nonce works once. |
| `email` | Up to 254 characters. |
| `email_verified` | `true` makes the email a verified identity, which matches the customer's email conversations to them. |
| `name` | 1 to 120 characters. |
| `phone` | E.164 form, such as `+14155550100`. |
| `avatar_url` | An `https` address, up to 2,048 characters. |
| `locale`, `timezone` | A language tag such as `en-US`, an IANA time zone such as `Europe/Paris`. |
| `company` | An object with `id` (required), `name`, `domain` and `custom_attributes`. |
| `custom_attributes` | Up to 100 keys of lowercase letters, digits and underscores, starting with a letter. Values are numbers, booleans, strings up to 1,024 characters, or `null` to remove the attribute. |

Attributes from a verified token are the only ones [dimmi agent actions](/ai/actions/) may bind to a customer.

## Use your auth provider's tokens

To skip signing, create a secret of the kind **Auth provider key set (JWKS)** with your provider's JWKS URL, then pass the provider's session token through `identity`. An empty **Issuer** means the key set address without its `/.well-known/` path.

## Rotate or revoke a secret

**Rotate** creates a new secret and keeps the old one working for 7 days. **Revoke** stops a secret at once, signs out every customer it signed in, and cannot be undone.

## Limits

| Limit | Value |
| --- | --- |
| Token size | 8 KB |
| Messenger session after the last verified token | 24 hours |
| Secrets per workspace | 5 |

## Check a token or require sign-in

Paste a token under **Check a token** in **Settings → Identity verification** to see its claims and why dimmi refuses it. On the same page, the **Required** sign-in mode hides the messenger from visitors who are not signed in.
