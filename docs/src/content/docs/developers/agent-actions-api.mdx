An [action](/ai/actions/) is one HTTPS request from dimmi to your API, built from the connection and the action you set up in **Settings → Actions**.

Your API must be on a public address: dimmi refuses private, loopback and link-local addresses.

## Authenticate dimmi

The connection's **Authentication** decides the credential dimmi adds to each request.

| Authentication | dimmi sends |
| --- | --- |
| **No auth** | No credential. |
| **Bearer token** | `Authorization: Bearer <token>` |
| **API key in a header** | The key in the header you name. |
| **API key in the query** | The key in the query parameter you name. |
| **Username and password** | `Authorization: Basic <base64 of username:password>` |

## Read the request headers

| Header | Value |
| --- | --- |
| `Dimmi-Action` | The action's tool name, such as `refund_invoice`. |
| `Dimmi-Action-Call` | The call's ID, `aax_...`. |
| `Dimmi-Workspace` | The workspace's ID, `ws_...`. |
| `Idempotency-Key` | The call's ID again, on actions set to **Changes data**. |
| `User-Agent` | `Dimmi-Actions/1 (+https://trydimmi.com/docs/ai/actions/)` |
| `Content-Type` | `application/json`, or `application/x-www-form-urlencoded` when **Body encoding** is form. |

The path, query and body are the action's own, with `{input.*}` filled by the dimmi agent and `{contact.*}` filled by dimmi from a [verified customer](/developers/messenger/identity-verification/). The agent cannot choose a `{contact.*}` value, so your API can treat it as the caller's identity.

```js title="server.js"
import express from "express";

const app = express();
app.use(express.json());

const invoices = new Map([["inv_1042", { customer: "cus_812", refunded: false }]]);
const answers = new Map(); // Use your database in production.

app.post("/v1/invoices/:id/refunds", (req, res) => {
  if (req.get("Authorization") !== `Bearer ${process.env.DIMMI_ACTIONS_TOKEN}`) {
    return res.status(401).end();
  }

  const key = req.get("Idempotency-Key");
  if (answers.has(key)) {
    return res.json(answers.get(key));
  }

  const invoice = invoices.get(req.params.id);
  if (!invoice || invoice.customer !== req.body.customer_id) {
    return res.status(404).json({ error: { message: "No such invoice." } });
  }
  if (invoice.refunded) {
    return res.status(409).json({ error: { message: "This invoice is already refunded." } });
  }

  invoice.refunded = true;
  const answer = { refund_id: "re_301", status: "pending" };
  answers.set(key, answer);
  res.json(answer);
});

app.listen(3000);
```

Set `DIMMI_ACTIONS_TOKEN` to the token you stored on the connection. The action's body here is `{"customer_id": "{contact.external_id}"}`.

## Answer with a status dimmi understands

| Your status | What dimmi does |
| --- | --- |
| `2xx` | Gives the agent the JSON fields listed under **Fields to keep**, or the whole body when none are listed. A body that is not JSON arrives as text. |
| `400`, `409`, `422` | Tells the agent the request was refused, with the first 300 characters of your message. Name its place in the body, such as `error.message`, in the action's `error_message_path` through the [REST API](/api-reference/). |
| `404` | Tells the agent nothing was found, with the same message. |
| `401`, `403` | Fails the call. After 3 in a row, the connection's actions stop until **Test connection** passes. |
| `429` | Fails the call as rate limited. |
| `3xx` | Fails the call. dimmi never follows redirects. |
| `502`, `503`, `504`, a timeout or no connection | Retries once for an action set to **Only reads data**. An action set to **Changes data** is sent once, never again. |
| Any other status | Fails the call. |

## Limits

| Limit | Value |
| --- | --- |
| Timeout | 8 seconds by default; **Timeout** on the connection takes 2 to 15 seconds. |
| Response body | 65,536 bytes by default. `response_max_bytes` in the API takes 1,024 to 262,144. |
| Result the agent reads | 8 KB after mapping. Lists keep 20 items, plain text 4,000 characters. |
| Default headers on a connection | 10, each value up to 256 characters. |

An action that needs approval sends the same request after the customer confirms or a teammate approves, up to 7 days after the agent proposed it.

## Connect an MCP server instead

A connection of the kind **MCP server** calls a remote server over Streamable HTTP, and each of its tools becomes an action.

- **Authentication** is **No auth**, **Bearer token** or **API key in a header**.
- **Headers.** dimmi sends `Dimmi-Action`, `Dimmi-Action-Call` and `Dimmi-Workspace`, and `Idempotency-Key` for a tool set to **Changes data**.
- **Sessions.** Each call opens a new session and closes it.
- **Results.** dimmi maps `structuredContent` like a JSON body and falls back to the text. A result with `isError` reaches the agent as a refusal with its first 300 characters.
- **Sync tools** reads up to 200 tools.
