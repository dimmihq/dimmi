---
title: "Secure your workspace"
description: "Restrict sign-in methods, set session timeouts, add IP allowlists, and require two-factor authentication."
---

Admins and Owners manage workspace security rules in **Settings → Security**. dimmi checks these rules on every request, so changes apply on each teammate's very next action.

## What each rule covers

| Rule | Browser and app sessions | API tokens |
| --- | --- | --- |
| **Sign-in methods** | Yes | No |
| **Session length** | Yes | No |
| **Dashboard IP allowlist** | Yes | No |
| **API IP allowlist** | No | Yes |
| **Require two-factor authentication** | Yes | Yes |

Every rule applies only to this workspace. Teammates can still access their other workspaces normally.

## Sign-in methods

Choose which login options teammates can use: **Password**, **Email link or code**, **Google**, **GitHub**, or **Single sign-on**. Self-hosted servers show whichever [sign-in providers](/self-hosting/sign-in-providers/) you turned on.

- **All checked:** no restriction. Future sign-in methods work too.
- **Google domains:** limit Google sign-in to specific company domains.
- **Lockout guard:** dimmi rejects any rule that excludes your own sign-in method or leaves no active Owner able to sign in.

To enforce SSO for an entire email domain, see [Set up single sign-on](/workspace/single-sign-on/).

## Session timeouts

- **Sign in again after:** max session age from full sign-in (1 hour to 30 days).
- **Sign out when idle for:** idle timeout (15 minutes to 7 days). Activity refreshes every 5 minutes, so a session can stay active up to 5 minutes past the exact limit.

Both default to **No limit**, capped by your server's global session limits.

## IP allowlists

Each allowlist accepts up to 100 entries (single IPs or CIDR ranges like `203.0.113.0/24`). Leave empty to allow all IPs.

- **Dashboard IP allowlist:** blocks saving a list that excludes your current IP address.
- **API IP allowlist:** applies to API tokens and CLI traffic.

## Require two-factor authentication

When turned on, teammates without an authenticator app cannot open the workspace, and their API tokens stop working there until they enroll.

- You must turn on two-factor authentication on your own account first.
- dimmi emails every active teammate who has not set it up yet.

## Audit trail and Owner alerts

Changes to sign-in methods, session timeouts, or IP allowlists are written to the [audit log](/workspace/audit-log/) with the new values, and dimmi notifies the other Owners by email.
