title: "Roles and permissions"
description: "See every permission included in Member, Admin, and Owner roles, and how to create custom roles."
---

Every workspace starts with three built-in roles, where each tier includes everything below it: **Member** (37 permissions), **Admin** (100), and **Owner** (111).

An [API token](/developers/api/abilities/) can never do more than the role of the teammate who created it.

## Custom roles

Create custom roles in **Settings → Roles** to give teammates a narrower set of Member or Admin permissions.

| Rule | How it works |
| --- | --- |
| **Base role** | Pick Member or Admin at creation. Cannot change later. |
| **Always included** | `members:read` is always granted. |
| **Owner permissions** | Cannot be granted to custom roles. |
| **Privilege guard** | You can only grant permissions you hold, and edit roles that contain no permissions you lack. |
| **Limit** | Up to 50 custom roles per workspace, each with a unique name. |
| **Live updates** | Editing a role takes effect on each member's next request. |
| **Assigning** | Owners cannot hold custom roles, and you cannot edit your own role. |
| **Deleting** | Allowed only after no one holds the role. |

Click **New role** to start from scratch or pick one of three presets:

| Preset | Base role | Includes |
| --- | --- | --- |
| **Support agent** | Member | Conversations, contacts, reading articles, notifications, personal signature, and AI features. |
| **Read only** | Member | Every Member permission ending in `:read`. |
| **Billing admin** | Admin | `billing:read`, `billing:write`, `settings:read`, and `members:read`. |
