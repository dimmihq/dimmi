---
title: "How workflows work"
description: "How dimmi picks which workflows run on a conversation, what stops a run, and how drafts and run history work."
---

A workflow runs a series of [steps](/workflows/triggers-and-steps/) on a conversation whenever its trigger fires. You can use workflows to greet customers, collect details, route threads, or call your own systems.

## Which workflows start

When a trigger fires, dimmi checks every live workflow with that trigger from the top of your **Workflows** list down.

- **Filters come first:** a workflow only starts if its **Audience**, **Channels**, **When it runs**, and **Once per conversation** rules all match.
- **Customer-facing workflows:** any workflow with a **Start of conversation** trigger, a **Messages** step, or **Let dimmi handle** takes ownership of the conversation while it runs. Only the first matching one starts.
- **Background workflows:** every other matching workflow runs, one after another in list order.
- **Loop protection:** a workflow never triggers itself, and a chain of workflows triggering each other stops after 3 hops.

When a customer-facing workflow finishes and the conversation is still open and unassigned, your inbox's [assignment rules](/inbox/how-assignment-works/) take over.

## What stops a run

A running workflow stops early in a few cases:

- **A teammate replies:** any reply to the customer ends all customer-facing runs on that thread right away.
- **The thread ends:** closing the conversation, marking it as spam, or deleting it stops every active run.
- **Safety limits:** a run fails if it passes 200 steps. Workflows send at most 20 messages per conversation per hour (extra messages are skipped), and no new run starts after 300 steps on one conversation in an hour.

## Drafts and versions

Edits save to a draft as you work. Your live workflow keeps running its published version until you click **Publish changes**.

Runs already in progress finish on the version they started with. Clicking **Pause** or **Archive** stops new runs from starting. Archived workflows leave the list and can only be restored through the API.

## Reusable workflows

A workflow with the **Run from other workflows** trigger only starts when another workflow hits a **Run a workflow** step. The parent workflow waits for it to finish, and both share saved values. You can nest reusable workflows up to 5 levels deep.

## Run history

Open **Runs** in the workflow builder to see the 20 most recent runs. Click any run to inspect what each step did.

| Status | What it means |
| --- | --- |
| **Waiting** | Paused for a customer reply, a timer, the dimmi agent, or a reusable workflow. |
| **Completed** | Reached the end of its path. |
| **Passed over** | A customer-facing run ended without sending a message or changing anything. |
| **Exited** | Stopped early because a teammate replied, the thread closed, or the customer did not pick a button. |
| **Failed** | Hit the 200-step limit or ran into an error. |
