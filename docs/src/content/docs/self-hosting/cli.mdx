Use `dimmictl` on the host to manage your Docker stack, and `/dimmi` inside containers for app administration, migrations, and diagnostics.

## `dimmictl` commands

Run `dimmictl` as `root`. Calling `dimmictl` with no arguments runs `install`.

| Command | What it does |
| --- | --- |
| `install` | Runs `prepare`, `configure`, `start`, and `check`. |
| `prepare` | Installs Docker, firewall rules, swap, and unattended security updates. |
| `configure` | Downloads stack files into `/opt/dimmi` and writes `.env` (preserving existing secrets). |
| `start` | Pulls images, runs database migrations, and starts all services. |
| `check` | Verifies DNS, HTTPS, and `/up`. |
| `admin --email <email> --name <name> --workspace <workspace>` | Creates the first Owner account and workspace, printing a generated password once. |
| `set KEY=value ...` | Writes settings to `.env` and restarts affected services. Reads `KEY=value` lines from stdin if given no arguments. |
| `update` | Upgrades to the latest release (or `--version`), migrates, and restarts. Saves customized `compose.yaml` or `Caddyfile` as `.bak`. |
| `status` | Lists running services and their health status. |
| `logs [service ...]` | Tails logs starting from the last 100 lines. |
| `help` | Prints available commands. |

## `dimmictl` options

`set` and `logs` take no flags.

| Option | Commands | Purpose |
| --- | --- | --- |
| `--domain <host>` | `install`, `configure` | Hostname for dimmi (no `https://` or path). |
| `--email <email>` | `install`, `configure`, `admin` | Let's Encrypt email for setup; user email for `admin`. |
| `--version <vX.Y.Z>` | `install`, `configure`, `update` | Release tag (defaults to latest; also reads `DIMMI_VERSION`). |
| `--clamav` | `install`, `configure` | Enables ClamAV malware scanning for uploads and email attachments. |
| `--skip-prepare` | `install` | Skips OS preparation (`prepare`). |
| `--image <image>` | `install`, `configure`, `update` | Overrides the default release container image. |
| `--dir <path>` | All | Stack install path (default `/opt/dimmi`; also reads `DIMMI_DIR`). |
| `--local-tls` | `install`, `configure`, `check` | Uses a self-signed certificate for local testing without public DNS. |
| `--name <name>`, `--workspace <workspace>` | `admin` | Full name and workspace name for the initial Owner. |

## Running `/dimmi` commands

```bash
docker compose -f /opt/dimmi/compose.yaml exec web /dimmi <command>
```

Every `/dimmi` command accepts `--help` and `--no-interaction` (`-n`, which accepts prompt defaults).

## Server management

| Command | What it does |
| --- | --- |
| `serve` | Starts the app (`--roles web,worker,scheduler`, `--no-migrate`). Managed automatically by Compose. |
| `health` | Exits `0` if ready, `1` otherwise. |
| `config:show` | Prints active settings with secrets redacted. |
| `down` | Enables maintenance mode (`--message <text>`, `--force`). |
| `up` | Exits maintenance mode. |

## Database migrations

`web` connects with a non-DDL database role. Run migration commands via the `migrate` service instead: `docker compose -f /opt/dimmi/compose.yaml run --rm migrate <command>`.

| Command | What it does |
| --- | --- |
| `migrate` | Applies pending migrations (prompts unless `--force` is passed). |
| `migrate:status` | Lists every migration and whether it has run. |
| `migrate:plan` | Previews migrations that `migrate` would run. |
| `migrate:rollback` | Reverts the latest migration (can drop data). Prompts for version confirmation (or pass `--force --confirm-version <version>`). |

## Users

| Command | What it does |
| --- | --- |
| `user:create` | Creates a verified user (`--email`, `--name`, and `--password <password>` or `--generate-password`). On a fresh server, pass `--workspace` to create the first workspace; afterward pass `--workspace-slug <slug> --role owner\|admin\|member`. |
| `user:list` | Lists accounts, 2FA factors, and workspaces (`--json`). |
| `user:reset-password <email>` | Prints a reset link, or sets a new password and signs the user out with `--password <password>`. |
| `user:verify-email <email>` | Marks the email address verified. |
| `user:logout <email>` | Revokes every active browser and app session for the user. |
| `user:disable-2fa <email>` | Clears all second factors for a locked-out account. |

## Workspaces

`<slug>` is the workspace identifier after `/w/` in the app URL.

| Command | What it does |
| --- | --- |
| `workspace:list` | Lists active and suspended workspaces (`--with-deleted`, `--json`). |
| `workspace:suspend <slug> --reason <text>` | Freezes writes on a workspace (members keep read access). |
| `workspace:unsuspend <slug>` | Restores writes to a suspended workspace. |
| `workspace:restore <slug>` | Restores a deleted workspace during its grace window. |
| `workspace:purge <slug> --force` | Permanently deletes a trashed workspace. |
| `workspace:repair [slug]` | Recreates missing defaults for one workspace (or all workspaces if omitted). |
| `workspace:clear-access-policy <slug>` | Clears lockout sign-in rules (`--only ip_allowlist` clears only IP rules). |

## Single sign-on and API tokens

| Command | What it does |
| --- | --- |
| `sso:verify-domain <domain>` | Verifies a workspace SSO domain without DNS (`--workspace <slug>` if multiple workspaces claimed it). |
| `sso:disable <slug>` | Disables all SSO connections for a workspace. |
| `token:create` | Creates an API token and prints it once (`--email`, `--workspace-slug`, `--name`, `--abilities` comma list or `*`, optional `--expires 90d`, `--json`). See [API token abilities](/developers/api/abilities/). |

## Email and AI diagnostics

| Command | What it does |
| --- | --- |
| `email:doctor <domain>` | Checks DNS and provider config for an outbound sending domain. |
| `email:inbound-doctor` | Diagnoses inbound mail delivery issues. |
| `email:cloudflare-worker` | Outputs the Cloudflare Email Routing Worker script. |
| `email:resend-backfill --since <YYYY-MM-DD>` | Replays inbound emails received by Resend since a date. |
| `ai:doctor` | Reports anything blocking the dimmi agent from answering and exits non-zero on failure. |
