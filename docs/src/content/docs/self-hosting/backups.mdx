---
title: "Back up and restore"
description: "Back up your dimmi database, files and app key, and restore them onto a new server."
---

A full backup is three things: `/opt/dimmi/.env`, a database dump and the files volume. Keep all three off the server.

## Back up

| What | Where | When |
| --- | --- | --- |
| Settings and secrets | `/opt/dimmi/.env` | Once, and after each `dimmictl set` |
| Database | A `pg_dump` of the `dimmi` database | Daily, and before each update |
| Uploaded files | The Docker volume `dimmi_seaweedfs` | Daily |

`.env` holds `DIMMI_APP__KEY`. Without that key, nobody can read the encrypted values in the database, and nothing can recover it. `.env` also holds the passwords the database and file store were created with.

Dump the database:

```bash
docker compose -f /opt/dimmi/compose.yaml exec -T postgres \
  pg_dump -U postgres -Fc dimmi > dimmi-$(date +%F).dump
```

Archive the files:

```bash
tar -czf dimmi-files-$(date +%F).tar.gz \
  -C /var/lib/docker/volumes/dimmi_seaweedfs/_data .
```

Valkey holds only the cache, rate limits and realtime messages, so it needs no backup.

## Restore onto a new server

1. Copy your saved `.env` to `/opt/dimmi/.env` on the new server.

2. Run the [installer](/self-hosting/install/) with the release you ran before. It keeps an existing `.env`, so the new database and file store get the same passwords and app key.

   ```bash
   curl -fsSL https://github.com/dimmihq/dimmi/releases/download/<version>/install.sh \
     | bash -s -- --version <version> --domain support.example.com --email ops@example.com
   ```

3. Stop the stack and put the files back.

   ```bash
   docker compose -f /opt/dimmi/compose.yaml stop
   tar -xzf dimmi-files-<date>.tar.gz -C /var/lib/docker/volumes/dimmi_seaweedfs/_data
   ```

4. Start the database alone and load the dump.

   ```bash
   docker compose -f /opt/dimmi/compose.yaml start postgres
   docker compose -f /opt/dimmi/compose.yaml exec -T postgres \
     pg_restore -U postgres -d dimmi --clean < dimmi-<date>.dump
   ```

5. Start everything with `dimmictl start`.

`<version>` is the release in the old server's `/opt/dimmi/VERSION` with a `v` in front, such as `v1.2.3`. `<date>` is the date in your backup's file name.
