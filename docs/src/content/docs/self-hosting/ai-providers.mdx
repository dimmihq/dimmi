---
title: "Add AI provider keys"
description: "Give your server Anthropic, OpenAI and embedding keys so the dimmi agent and Operator work for every workspace."
---

Keys set on the server give every workspace a built-in AI provider. Without them, each workspace adds its own keys in **Settings → AI providers** ([AI providers](/ai/providers/)).

```bash
dimmictl set <<'EOF'
DIMMI_AI__MANAGED__ANTHROPIC__API_KEY=<anthropic_api_key>
DIMMI_AI__MANAGED__OPENAI__API_KEY=<openai_api_key>
DIMMI_AI__MANAGED__EMBEDDINGS__API_KEY=<embeddings_api_key>
EOF
```

- **Models:** set the Anthropic key, the OpenAI key or both. The built-in provider offers only the models of a provider whose key is set.
- **Embeddings:** this key powers semantic search of knowledge sources. Without it, a workspace gets semantic search only from an OpenAI key of its own.

## Options

Each variable starts with `DIMMI_AI__`.

| Variable | Default | Description |
| --- | --- | --- |
| `MANAGED__ANTHROPIC__BASE_URL` | Anthropic's API | Another address for Anthropic requests, such as a proxy. |
| `MANAGED__OPENAI__BASE_URL` | OpenAI's API | Another address for OpenAI requests. |
| `MANAGED__EMBEDDINGS__BASE_URL` | `https://api.deepinfra.com/v1/openai` | An OpenAI-compatible embeddings API. |
| `MANAGED__EMBEDDINGS__MODEL` | `Qwen/Qwen3-Embedding-8B` | The embedding model. It must produce 1024 dimensions. |
| `DEFAULT_MONTHLY_CAP_USD` | `25` | The monthly spending cap a new workspace's dimmi agent starts with, in US dollars. |
| `ENABLED` | `true` | `false` turns the dimmi agent off on the whole server. |

To list what stops the dimmi agent from answering, run:

```bash
docker compose -f /opt/dimmi/compose.yaml exec web /dimmi ai:doctor
```
