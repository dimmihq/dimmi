title: "Install dimmi on a server"
description: "Deploy dimmi on a Linux server in one command, create your first Owner account, and sign in."
---
import { Steps } from "~docs/components/mdx";

Make sure your server meets the [requirements](/self-hosting/) and pick a hostname you control, such as `support.example.com`.

<Steps>

1. Create an `A` record at your DNS provider pointing your hostname to the server's public IPv4 address.

2. Run the installer on your server as `root` (takes 3 to 5 minutes):

   ```bash
   curl -fsSL https://github.com/dimmihq/dimmi/releases/latest/download/install.sh \
     | bash -s -- --domain support.example.com --email ops@example.com
   ```

   `--email` receives Let's Encrypt certificate notices. Running as a `sudo` user? Pipe to `sudo bash -s -- ...` instead.

3. Create your first Owner account. Self-hosted installs start invite-only, so this Owner invites the rest of your team from inside the app:

   ```bash
   dimmictl admin --email ada@example.com --name "Ada Lovelace" --workspace "Acme Inc"
   ```

   Copy the generated password printed once in your terminal.

4. Open `https://support.example.com`, sign in, and change your password.

</Steps>

You can rerun the installer with the same flags anytime; it preserves all previously generated secrets. See the [command-line reference](/self-hosting/cli/) for all installer flags.

## Read login links before configuring email

Until you [connect a mail provider](/self-hosting/email/), dimmi logs outgoing emails instead of sending them. Grab an invite or sign-in link from your logs with:

```bash
dimmictl logs web worker | grep mail_fallback
```
