---
title: "How Operator changesets work"
description: "How Operator proposes workspace changes as reviewable cards, when changes apply on their own, and how undo works."
---

Whenever **Operator** wants to edit your workspace, it bundles the changes into a **changeset**: a single review card (up to **50 changes**) that a teammate can apply, decline, or undo in one click.

This keeps your team in control so AI never silently breaks tags, routing, or live help articles.

## What Operator can change

Admins choose a policy for each group under **Settings → Operator → What Operator may change**: **Ask first** (the default), **On its own**, or **Off**.

| Group | What it can change | Allowed **On its own**? |
| --- | --- | --- |
| **Conversations** | Tags, assignment, priority, status, and subject | Yes |
| **Internal notes** | Adding a private note to a thread | Yes |
| **Customers** | Updating a customer's name | Yes |
| **Help articles** | Creating a new draft or editing a draft | No |
| **Procedures** | Editing a procedure's working copy and adding saved simulations (tests) | No |
| **Workspace actions** | Running an [action](/ai/actions/) that changes data | No |

Operator never publishes a help article or a procedure. Publishing always stays with a teammate.

Even when a group is set to **On its own**, Operator still asks a teammate first whenever it triages a new chat or bases its edit on untrusted conversation text or an external action response.

## Changeset states

| Card badge | Meaning |
| --- | --- |
| **Waiting for you** | Proposed and waiting for a teammate to apply or decline. |
| **Applied** / **Applied on its own** | Every change in the card succeeded. |
| **Declined** | Rejected; nothing in your workspace changed. |
| **Not applied** | One item failed, so dimmi rolled back the whole card. Fix the issue and click **Try again**. |
| **Undone** | Previous values were restored. |

## How apply and undo work

- **All or nothing:** dimmi applies every change in a changeset inside one transaction, so partial edits never happen.
- **Runs as you:** every change checks the permissions of the teammate who clicks **Apply**. Actions that require an admin must be approved by an admin.
- **Smart undo:** clicking **Undo** restores each previous value in reverse order and skips any field a teammate edited afterward.
- **Content undo:** internal notes are removed; drafted articles are removed only if never published; added procedure simulations are removed; draft edits revert only if nobody edited the text since.
- **External actions cannot undo:** once a workspace action calls your external API, dimmi cannot roll it back.
- **Works in Slack and audit logs:** Slack cards show the same **Apply**, **Decline**, and **Undo** buttons, and every decision is logged under the teammate in the [audit log](/workspace/audit-log/).
