---
title: "Link Linear, Jira, and GitHub issues"
description: "Connect dimmi tickets to issues in Linear, Jira, or GitHub so status updates flow both ways and engineers see customer impact."
---

Connect Linear, Jira, or GitHub in **Settings → Integrations**. Once connected, click **Link issue** on any ticket to create a new issue or link an existing one.

## What syncs between dimmi and your tracker

| Direction | What syncs |
| --- | --- |
| **Tracker → dimmi** | Status changes move the dimmi ticket to a matching state. Customers only ever see dimmi states. |
| **Tracker → dimmi** | Comments posted on the issue show up as internal notes on the ticket. |
| **dimmi → Tracker** | Live customer impact: affected customers, companies, conversations, revenue at stake, and up to 10 company names. dimmi updates this whenever links change. |

Updates arrive in real time via webhooks, and dimmi also refreshes every open link every 15 minutes as a backup. Click **Refresh** on a ticket's linked issues to pull updates right away.

## Map issue statuses to ticket states

Open your integration settings and go to **Statuses** to map each status to a dimmi state. In Linear and Jira, open each team or project to map its own statuses.

Any status you leave unmapped uses these defaults:

| Issue status category | Ticket moves to |
| --- | --- |
| **Started** | **Being worked on** |
| **Done** | **Close the loop** |
| **Canceled** | **Won't fix** |
| **Backlog or not started** | Stays where it is. |

dimmi caches teams and statuses from your tracker for 1 day. If you add a new team or status, click **Refresh** to load it right away.

If a ticket rule blocks a state change (such as a missing required field), the ticket stays put and the link shows a warning.

## Close the loop with customers

When an engineering issue finishes, dimmi moves the ticket to **Close the loop**. Nothing goes out to customers automatically. Either a teammate replies, or a workflow with the **Ticket needs the loop closed** [trigger](/workflows/triggers-and-steps/) sends the update.

Unlinking an issue leaves it untouched in Linear, Jira, or GitHub. Tick **Also remove what dimmi wrote** to remove the impact block and ticket link too (in the API, pass `remove_from_tool=true`).
