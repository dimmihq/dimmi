# 00 Accounts: interface language (T-05)

Style: caveman. Track 07. Server side exists: `framework/i18n`, `lang/en/*.json`, `app.locales`, `lang:check`, recipient-locale mail. Missing: browser app has literal English everywhere, no locale setting works. Customer-facing language of widget and help center: 01, 08, not here.

## Decisions

| # | Decision | Why |
|---|---|---|
| L1 | Browser library: `i18next` + `react-i18next`, tooling `i18next-cli` (all MIT). | Mature; interpolation `{{name}}` and CLDR plural suffixes match how `lang/` files already read; `i18next-cli` has `extract --ci`, `lint` for hardcoded JSX text, `status`. Reuse check: i18next-cli verified 2026-11-04 (MIT, commands present). Dev dependency for CLI; runtime two packages. Pin exact versions |
| L2 | Ship order: `en`, then `fr`, `de`, `es`, `pt-BR`. | Same set page already advertises and Intercom ships. All left-to-right; layouts already use logical CSS rules, so an RTL language is a content step when owner picks one |
| L3 | Translation is content work. **Machine-assisted first pass, human review before release.** | Fast and cheap; machine text alone reads badly in a tool people use all day |
| L4 | Locale is listed in `app.locales` only after human review. Engineering ships with `["en"]`. | Half-translated language worse than none. Control hidden with one locale |
| L5 | Extraction happens last in wave, one milestone. Lint gate turns on after. | Other wave-1 tracks are adding screens now; extracting early causes merge conflicts in every file |
| L6 | Fallback: user locale -> workspace locale -> browser `Accept-Language` match -> `en`. Missing key shows English. | Same chain as server `Negotiate` |
| L7 | No per-tenant copy overrides. | No gap asks |

Human step for L3: owner names reviewer per language. Machine pass: one-off by a person using a translation service or an LLM, outside tests and CI, cost roughly under $20 per language at current catalog size (estimate; actual run needs owner approval, per user rule on LLM spend). Result committed like any file. dimmi never calls translation API at build or run time for this.

## Data

No new columns: `users.locale` exists, nullable; `workspaces.locale` exists. `PATCH /user {locale}`: value in `app.locales` (BCP 47), else 422 `errors.locale` (rule `locale`, already registered from `app.locales`); null = follow workspace. Migration none. X6: 00-accounts owns write.

`/me.user.locale` raw value (null when unset); `/me.locale` resolved: user's, else the workspace in play (named by `Dimmi-Workspace` or a token's own), else the request's language. Server re-runs the locale middleware after `auth` and after `workspace` (aliases wrapped in `RouteServiceProvider`), so every authenticated route reads user, then workspace, then `Accept-Language`; a locale no longer served is skipped (`appauth.PreferredLocale`). `GET /auth/config` adds `locales: [{code, name}]` (native name from `lang/<code>/meta.json`), for login pages and pickers.

## Frontend

Files:
- `resources/js/lang/<locale>/<namespace>.json`. Namespaces per feature folder: `common`, `auth`, `inbox`, `settings`, `shell`, `automation`. Today only `common` and `settings` exist; the others arrive with extraction. Keys dotted, stable, English value is source. `en` bundled; others lazy chunks via Vite dynamic import (`i18next` backend hand-written in 15 lines, no extra package).
- `resources/js/lib/i18n/{index,format,locale-sync}.ts`. `index`: init. `format`: `Intl` wrappers for date, time, number, relative, list, all taking active locale + user time zone. Replaces ad hoc formatting (`lib/location.ts` stays for zone).
- `resources/js/features/settings/preferences/language-row.tsx`: `LanguageRow` (Preferences) and `WorkspaceLanguageRow` (workspace page).
- `resources/js/features/shell/locale-root.tsx`: wraps the router, runs `useLocaleSync`, renders `DirectionProvider`, writes `<html lang dir>` from React Aria's locale. With one locale served it fetches only `/auth/config`.

Mechanics:
- `main` wraps app in BoardUI `DirectionProvider` with `locale` (React Aria keyboard + date formats follow) and sets `<html lang dir>`.
- Pick language: `PATCH /user`, `i18next.changeLanguage`, no reload. Query cache cleared for server-translated messages only (`["me"]`).
- API sends `Accept-Language: <active>` so server errors and validation match. Server `framework/i18n` negotiates per request; authenticated request prefers `users.locale`, then workspace.
- Pre-login pages: browser language if in list. After login: user wins.
- Plurals via `count`. Never concatenate sentences; interpolate. Rich text via `<Trans>`.
- `log-labels.ts`, `invitation-text.ts`, `session-detail.ts`: move to keys; test files updated.
- BoardUI folders (`components`, `styles`, `utils`) hold few strings; those with text take props; Aria built-ins translate themselves. Lint `lint` config excludes them.
- Command menu (03 track 03) registers action "Change language", calling same setter, when more than one locale.

Pseudo-locale `en-XA`, generated by `scripts/pseudo-locale.ts` (`make pseudo-locale`; `make dev` and `make e2e` run it) from the English files of `resources/js/lang/en` and `lang/en` (accented, 30% longer, placeholders kept). Output gitignored; `lang/lang.go` embeds `*/*.json` so a generated directory ships but is never served unless listed. Framework messages (`validation.required` and others built in Go) stay English in `en-XA`, so `lang:check` reports them missing while the generated directory exists. Enabled in `dimmi.example.yaml` (dev) and `tests/e2e/server.ts` (`DIMMI_APP__LOCALES=en,en-XA`), never `app.locales` in release (`tests/arch/locales_test.go`). Proves no literal remains and layout survives long words.

## UI

## Edge cases

- Locale removed from `app.locales` while user holds it: resolver falls to next; `/me.user.locale` kept; picker shows "Workspace default".
- Mail: `Locale(user.locale or workspace.locale)` exists; unchanged.
- Translation adds string with `{{name}}` missing: `lang:check` and test fail on placeholder mismatch (framework `keys.go`; add browser check in same script).
- Customer content (messages, tags): never translated here; I-translation in 03.
- Date inputs: BoardUI `date-picker` via React Aria, follows locale.
- RTL: no RTL locale ships; `dir` set from locale anyway.
